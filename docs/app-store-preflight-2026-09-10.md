## Блокеры и оставшиеся проверки

1. **Методика сканера.** `services/scanning/result-interpretation.ts` автоматически предлагает positive/negative, включая fallback по обнаруженной тестовой полоске без настроенного cutoff. Пакет доказательств точности в рамках этого аудита не найден. Нужны материалы по поддержанным тестам, методике, ограничениям и валидации для правила 1.4.1. Пользовательское подтверждение и дисклеймер не доказывают точность. Не выключать функцию только для ревью и не включать скрытно после него.
2. **Политика приватности.** `https://brainwaves.engineering/docs#document-2` доступна (HTTP 200), но прочитанный HTML содержит общие корпоративные документы, без названия приложения, Yandex AI Studio и специфичного 30-дневного удаления. Нужна согласованная с фактической обработкой политика приложения: категории данных, цели, поставщики, синхронизация, хранение, удаление, контакты. Не публиковать выдуманные юридические обязательства.
3. **iOS identity.** `app.json`, текущий Xcode project и `admin/public/.well-known/apple-app-site-association` пока настроены на `2675845GP5.com.anonymous.privateexpo`. Создать отдельную production-конфигурацию для нового team/bundle, сохранив прежнюю тестовую; обновить AASA согласованно.
4. **Резервные копии медицинских файлов.** `lib/local-files.native.ts` сохраняет фотографии и документы в Documents. Явного исключения из iCloud Backup в проверенном коде не найдено. Проверить и исправить на нативном iOS; правило 5.1.3 запрещает хранение персональных медицинских данных в iCloud. SQLCipher не исключает файлы из backup автоматически.
5. **Разрешения и privacy manifest.** В текущем сгенерированном Info.plist есть общее английское разрешение микрофона. Проверить необходимость, убрать ненужное через Expo config; проверить итоговый archive и manifests всех SDK. Пустой collected-data массив не является доказательством отсутствия сбора данных. App Privacy в Connect заполнить по фактическим потокам.
6. **Шифрование.** Используется SQLCipher, поэтому нельзя автоматически объявлять отсутствие/исключение шифрования. Пройти экспортную анкету Apple с точными сведениями об алгоритмах и странах; при необходимости получить подтверждающие документы.
7. **Ревью-доступ.** Создать отдельный обычный аккаунт приложения с синтетическими данными, без административных прав, без обязательного Apple/SMS-входа. Его ещё не создали. Передать credentials в App Review Information, не в Git; проверить вход в release build. Подготовить безопасный демонстрационный QR/инструкции для сканера.
8. **Нативный выпуск.** IPA не собран и не валидирован. Требуются release-тесты iPhone/iPad: вход, онбординг, камера/отказ в разрешении, дневник, удаление, offline, согласия ИИ, отсутствие crashes; затем реальные screenshots, возрастная анкета, support URL, точные metadata и App Store Connect validation. Проверить лицензии поставляемых шрифтов/изображений.
