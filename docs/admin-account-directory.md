# Админка: аккаунты и реальные данные

## Границы доступа

`adminUsers:list` доступен только действующим администраторам. DTO содержит
только `id`, `email`, `registeredAt`, `status`. Нет доступа к профилям здоровья,
фотографиям, документам, чатам, паролям и токенам. Управление аккаунтами не добавлено.
Поиск — по началу нормализованного email через существующий индекс. Страница
ограничена 50 строками. Статус отражает наличие отложенного удаления аккаунта.

`adminUsers:overview` читает только материализованные счётчики. Сумма дневной
активности не обозначается как MAU. Регистрации за период используют UTC.

## Пересчёт и выпуск

Развёртывание этой работы требует отдельного согласования. Сначала развернуть
Convex schema/functions штатным защищённым workflow, затем пересчитать старые
аккаунты, затем выпустить статическую админку. Не запускать seed ради заполнения UI.

На согласованном deployment оператор повторяет
`npx convex run adminUsers:backfill '{}' --env-file .env.local`, пока ответ не
содержит `complete: true`. Каждый вызов обрабатывает максимум 50 аккаунтов,
сохраняет курсор транзакционно и безопасен для повторного запуска. Автоматического
запуска с публичной страницы нет. Пока пересчёт не закончен, UI явно сообщает
о неполной статистике, но список аккаунтов уже работает.

Создание аккаунта и его окончательное удаление обновляют счётчики в той же
транзакции; ledger предотвращает повторное добавление. Удаление снижает текущее
количество аккаунтов, но не стирает агрегированное число регистраций.
История пользователей, удалённых до появления счётчиков, неизвестна и не
восстанавливается. Поэтому исторические регистрации до первоначального
пересчёта отражают только сохранившиеся к нему аккаунты.

При откате фронтенда новые таблицы и серверные hooks оставить: удаление
счётчиков приведёт к потере накопленной истории. Перед повторным rollout
проверить `complete` и актуальность серверного API.

## Проверки

- `npm run test:admin` — изолированная Convex-база, права, DTO, пагинация,
  счётчики и миграция, включая создание/удаление между пакетами.
- `npm run test:admin-ui` — браузерные сценарии с локальными тестовыми данными.
  Стенд использует реальные компоненты, но тестовые hooks, и никогда не входит
  в `admin/out`. Он не доказывает доступ к production или запись в production.
- `npm run preview:admin-ui` — локальный стенд на `127.0.0.1:4319`, помеченный
  «тестовые данные, не production». Нет возможности записывать данные.
- `npm run verify` и `npm --prefix admin run verify` — проверки и сборки.

## Read-only проверка публикации 2026-09-11

Сайт `https://artificiallabs.bebra42.ru/` вернул HTTP 200. Проверенные публичные
JS-файлы содержат ожидаемый endpoint `artificiallabs-convex.bebra42.ru`, но не
новый раздел аккаунтов. Метаданные действующего Convex содержат `admin:viewer`,
`adminCatalog:listTestSystems`, `monitoringData:latest`, `telemetry:overview`;
`adminUsers:list` пока отсутствует. Персональные строки production не выгружались.
Это подтверждает адрес подключения и отсутствие нового API, но не число
реальных пользователей и не содержимое каталогов. Production не обновлялся.
Прямые анонимные вызовы `admin:viewer` и `adminCatalog:listTestSystems`
возвращают `UNAUTHENTICATED`; доступ гостю закрыт.

## Результат локальной проверки

11 сентября 2026: `npm run test:admin` — 15 тестов; `npm run test:admin-ui` —
6 браузерных сценариев; `npm run verify` и отдельный
`npm --prefix admin run verify` завершились успешно. `git diff --check` чистый.
Desktop/mobile снимки находятся в игнорируемом `output/playwright/` и содержат
только явно помеченные тестовые данные. Production deploy и пересчёт реальных
аккаунтов не выполнялись. Параллельные изменения мобильного профиля и смены
email сохранены, не входят в эту доработку админки.
