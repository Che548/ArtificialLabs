# Структура исходного кода

Этот справочник показывает, где находится ответственность за каждую часть системы. Он описывает только файлы, отслеживаемые Git в коммите `80c41c1`; локальные эксперименты и невыбранные изменения в состав проекта не включены.

> [!summary] Как искать место изменения
> Маршрут и сборку экрана ищите в `app/`, визуальный компонент — в `design-system/`, предметное правило — в `lib/` или `services/`, серверный контракт — в `convex/`, нативный анализ изображения — в `modules/strip-cv/`.

## Верхний уровень репозитория

| Путь | Ответственность | Не следует размещать |
|---|---|---|
| `app/` | маршруты Expo Router и подключение данных к экранам | правила хранения и серверную авторизацию |
| `components/` | вход, начальная настройка и общие проверки состояния | самостоятельные медицинские хранилища |
| `design-system/` | токены, базовые элементы, составные страницы и модальные сценарии | сетевые вызовы и прямой доступ к БД |
| `lib/` | предметные вычисления, HealthStore, локальная БД, синхронизация, уведомления, ИИ-контекст и телеметрия | административные полномочия |
| `services/scanning/` | оркестрация сканирования, QR-профили, интерпретация и история | реализацию C++-алгоритма |
| `modules/strip-cv/` | модуль Expo, нативные мосты и переносимое ядро C++/OpenCV | медицинские решения без подтверждения пользователя |
| `convex/` | схема, аутентификация, персональные и административные функции, задания и мониторинг | секреты окружения и исходные медицинские файлы |
| `admin/` | отдельная консоль Next.js и статический экспорт | клиентские проверки как единственный контроль доступа |
| `tests/` | серверные, веб- и интеграционные проверки | производственные данные и постоянные реквизиты |
| `.maestro/` | нативные сквозные сценарии | медицинские образцы и секреты |
| `scripts/` | сборка, локальные серверы и проверки покрытия | скрытые производственные операции |
| `infra/` | развёртывание Convex и веб-контейнера | исходный код приложения в конечном образе |
| `.github/workflows/` | автоматические проверки и защищённый выпуск | административные ключи в заданиях pull request |
| `shared/` | общие неизменяемые контракты, включая тексты уведомлений | платформенную реализацию |
| `ArtificialLabs/` | историческая версия Swift | код текущего приложения Expo |

## Серверная часть

`convex/` разделён по предметным областям. Файлы `health.ts`, `profile.ts`, `account.ts`, `chat.ts`, `agent.ts` и `notifications.ts` обслуживают пользователя. `admin*.ts`, `publicCatalog.ts` и `calibrationActions.ts` управляют административными и публичными данными. `telemetry.ts`, `monitoring.ts`, `monitoringData.ts` и `crons.ts` отвечают за эксплуатационные сигналы и плановые задания.

Повторяемые проверки доступа находятся в `convex/lib/access.ts` и `convex/lib/adminAccess.ts`. Провайдер Yandex AI изолирован в `convex/ai/yandexProvider.ts`; конфигурация, пределы и версии согласий определены в `aiChatConfig.ts` и `aiAgentConfig.ts`.

## Сгенерированные и локальные данные

`convex/_generated/` изменяется средствами Convex. Каталоги `ios/`, `android/`, `dist/`, `web-build/`, `admin/out/`, результаты E2E, `.maestro/runtime/`, файлы окружения и локальное хранилище `docs/artificial-labs/` не публикуются как исходный код.

> [!warning] Не смешивать с исходниками
> Сгенерированный файл может быть необходим для проверки, но это не делает его местом ручного изменения. Секрет, временный медицинский образец или артефакт выполнения не становится частью функции проекта только потому, что находится в рабочем каталоге.

## Проверка состава перед документированием

```bash
git status --short --branch
git diff --stat
git diff --cached --stat
git ls-files
git diff --name-status <базовый-коммит>..HEAD
```

Сначала определяется зафиксированный состав, затем обновляются код, проверки и документация одной и той же возможности. Неотслеживаемый каталог или незакоммиченный файл не используется как источник поддерживаемого поведения.
