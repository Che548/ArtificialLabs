# Архитектура приложения

Сервисная топология, согласия/OCR и синхронизация актуализированы 2026-09-13
по main `2837cda34bc06c8adf0251c11bbad0bf203af824`:
[текущая система](../../architecture/service-architecture.md),
[модель данных](../../architecture/database-model.md).
Эта отметка относится к указанным разделам, а не к повторной проверке всех
исторических описаний интерфейса ниже.

ArtificialLabs состоит из нативного приложения, серверной части Convex и отдельной административной консоли. Главный архитектурный принцип — локальное завершение медицинской записи: приложение сначала сохраняет данные на устройстве и только затем, при отдельном согласии пользователя, пытается синхронизировать разрешённую структурированную часть.

> [!summary] Архитектурное решение
> iOS и Android работают по модели «локально прежде всего». Исходники и URI не входят в обычный health sync. Отдельный согласованный облачный OCR передаёт подготовленную страницу через HTTP action провайдеру; это временная обработка, не сохранение документа в Convex. Expo Web — демонстрация; `admin/` не получает персональные медицинские таблицы.

## Состав системы

| Компонент | Назначение | Граница доверия |
|---|---|---|
| Expo SDK 54 и React Native 0.81 | пользовательские сценарии iOS и Android | обрабатывают медицинские данные на устройстве |
| SQLCipher SQLite | основное локальное хранилище и исходящая очередь | ключ хранится в SecureStore только на данном устройстве |
| Каталог документов приложения | фотографии тест-полосок и исходные документы | содержимое не включается в облачную синхронизацию |
| Convex | аутентификация, необязательная синхронизация, уведомления, ИИ-функции, каталоги и эксплуатационные данные | каждая персональная операция проверяет пользователя и владельца профиля |
| `admin/` | защищённая статически экспортируемая консоль Next.js | полномочия подтверждает серверная функция `requireAdmin()` |
| Expo Web | демонстрация интерфейса | медицинские записи не сохраняются |
| StripCV | анализ тест-полоски на устройстве | результат предварительный и требует подтверждения пользователя |

## Запуск приложения

Корневой макет `app/_layout.tsx` создаёт среду выполнения в следующем порядке:

```text
ConvexAuthProvider
  → ConnectivityProvider
  → проверка платформы и состояния входа
  → HealthStoreProvider
  → NotificationManagerProvider
  → TelemetryManager
  → AgentAutomationManager
  → AppGate
  → навигация приложения
```

На нативной платформе токен Convex Auth хранится через `lib/secure-storage.ts` с режимом `WHEN_UNLOCKED_THIS_DEVICE_ONLY`. Ошибка чтения закрывает доступ и возвращает приложение к входу, а не прерывает запуск поставщика аутентификации. В веб-демонстрации постоянное хранилище токена не подключается.

## Запись и синхронизация

```text
Экран
  → HealthStore и предметная логика
  → транзакция SQLCipher
  → идемпотентная запись в исходящую очередь
  → успешное завершение локальной операции
  → синхронизация при наличии согласия и сети
  → функция Convex с проверкой владельца
```

Сетевая ошибка не отменяет завершённую локальную запись. Элемент очереди остаётся ожидающим, временные сбои повторяются с ограниченной задержкой, а ошибки аутентификации и проверки данных не маскируются под транспортные. Возврат соединения запускает одну согласованную попытку синхронизации.

Текущее согласие хранится на уровне Auth-сессии в `cloudSyncSessions`, а не
выдаётся самим входом. Protocol 1 проверяет ревизии записей и merge base
профиля; ACK относится к точному payload. Конфликт требует явного выбора
версии. Старые клиенты при разрешённой legacy-совместимости сохраняют
timestamp-политику и её ограничения. [Подробности](../../multi-device-sync.md).

## Локальные вычисления для интерфейса

Последние изменения выделили вычисления из компонентов в детерминированные модули:

| Модуль | Ответственность |
|---|---|
| `lib/cycle-insights.ts` | календарные границы, фактические периоды, длина цикла, окно фертильности и задержка |
| `lib/health-insights.ts` | сегменты цикла и интенсивность только из явно сохранённых ответов дневника |
| `lib/journal-options.ts` | взаимоисключающие варианты ответа в дневнике |
| `lib/product-insights.ts` | режим главного экрана, неделя беременности, заполненность дневника и выполнение плана наблюдения |

Эти функции получают сохранённые данные и не создают медицинские факты из оформления экрана. Прогноз цикла является ориентиром, а не диагнозом или способом контрацепции. Если исходных данных недостаточно, интерфейс должен показывать отсутствие сведений, а не правдоподобное вымышленное значение.

## Сканирование

```text
Экран сканирования
  → services/scanning
  → типизированный интерфейс modules/strip-cv
  → Swift/Objective-C++ или Kotlin/JNI
  → C++ и OpenCV
  → значение, качество, версия алгоритма и происхождение
  → ручная проверка границ и результата
  → локальное сохранение
```

Фотография остаётся в каталоге приложения. В структурированной записи сохраняются числовой результат, признаки качества, уверенность, источник и версия алгоритма. Окончательное значение остаётся явно подтверждённым пользователем.

## Диалог и план наблюдения

Обычный диалог и помощник с доступом к ограниченному медицинскому контексту имеют разные согласия и серверные флаги. Контекст помощника ограничен по объёму и времени, данные считаются недоверенными, а доступные инструменты выполняют только чтение.

Проверка плана наблюдения допускает не более заданного числа рекомендаций из серверного каталога. Некорректный ответ модели повторно формируется в рамках ограниченной попытки. Если обе генерации не проходят проверку, сервер возвращает консервативный план из собственного каталога с поставщиком `server-catalog`. Интерактивные и плановые проверки используют раздельные пользовательские лимиты и общий системный лимит.

> [!warning] Медицинская граница
> ИИ-ответ и автоматически предложенный план не являются назначением врача. Флаги, согласие, проверка структуры и резервный план снижают технический риск, но не доказывают клиническую корректность.

## Административная консоль

`admin/` экспортируется в `admin/out` и обслуживается nginx. Статические файлы не содержат секретов и не принимают решений о полномочиях. Любая серверная операция повторно вызывает `requireAdmin()`.

Консоль управляет администраторами, каталогами, партиями, калибровками, публикациями, обезличенными агрегатами, проверками сервисов и аудитом. Персональные медицинские таблицы, чат, журнал, сканы и документы пользователя не входят в её допустимую поверхность.

Дополнительно разрешён защищённый read-only directory аккаунтов: ID, email,
дата регистрации и статус, без медицинских профилей/токенов. Публичная
страница `/beta/` не подключает Auth/Convex providers. На отдельном
установочном хосте `/` временно перенаправляет в `/beta/`; это не отменяет
защиту `/` административного хоста и `/kit`.

## Платформенные границы

Файлы `.native` реализуют SQLCipher, локальные файлы, уведомления, фоновую работу и очереди. Файлы `.web` предоставляют режим чтения либо явно безопасное отсутствие операции. Пакет `admin/` развёртывается отдельно и не расширяет возможности Expo Web.

Сохранённые каталоги `ArtificialLabs/`, `ArtificialLabs.xcodeproj/` и `project.yml` относятся к исторической Swift-версии. Они не являются текущей средой выполнения и не должны смешиваться с нативными каталогами, которые генерирует Expo.

## Неприкосновенные свойства

1. Медицинская запись завершается локально до сетевого обращения.
2. Исходники не включаются в обычный sync/storage; отдельная передача OCR-страниц провайдеру требует собственного согласия и серверного разрешения.
3. Облачная синхронизация включается отдельно на каждом устройстве.
4. Сервер проверяет аутентификацию и принадлежность персональных данных.
5. Административная консоль не получает доступ к медицинским таблицам.
6. Expo Web не записывает медицинские данные.
7. StripCV и прогнозы интерфейса не представляются диагностическими результатами.
8. Ошибка сети не уничтожает завершённую локальную запись.
9. Отсутствующие данные не заменяются вымышленными значениями.

Изменение любого из этих свойств требует пересмотра модели угроз, классификации данных, матрицы приёмочных проверок и пользовательского объяснения.
