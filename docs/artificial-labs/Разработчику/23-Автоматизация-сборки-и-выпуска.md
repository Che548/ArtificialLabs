# Автоматизация проверки и развёртывания

Документ описывает рабочие процессы GitHub Actions и границы доступа к секретам.

## Непривилегированная проверка

`.github/workflows/ci.yml` запускается при отправке изменений и создании запроса на слияние с правом `contents: read`.

Последовательность:

1. получение исходного кода;
2. настройка Node.js из `.nvmrc` и кэша npm;
3. `npm ci`;
4. `npm --prefix admin ci`;
5. `npm test`;
6. установка CMake и OpenCV;
7. `npm run test:strip-cv`;
8. `npm run verify`, включая Expo Web и сборку административного приложения.

Параллелизм отменяет предыдущий запуск для той же ссылки Git. Секреты не используются.

## Живые сквозные испытания

`e2e-live.yml` доступен только через `workflow_dispatch` и получает административный ключ Convex и отдельные E2E-учётные данные администратора. Процесс развёртывает выбранные функции, проверяет привязки, запускает модульные и серверные E2E, проверяет защищённую административную консоль Playwright и сохраняет обезличенные подтверждения на 14 дней.

Добавление события `pull_request` или выполнение недоверенного кода с ключом запрещено.

## Публикация GHCR

`ghcr-publish.yml` запускается при отправке изменений в `main` и вручную. После проверки обязательных файлов выполняются `npm ci`, `npm --prefix admin ci`, `npm run verify`, защищённое развёртывание Convex, проверка привязок, сборка `linux/amd64` и публикация меток SHA, ветви и `latest`.

Ручной запуск другой ветви также обновляет `latest`, после чего Watchtower может развернуть эту версию.

## Граница сгенерированных привязок

`e2e-live.yml` и `ghcr-publish.yml` выполняют `git diff --exit-code -- convex/_generated`, но только после `npx convex dev --once`. Обычная проверка запроса на слияние не запускает генерацию привязок Convex. Поэтому текущая проверка обнаруживает расхождение в защищённом процессе, но не предотвращает отправку функций до обнаружения и не доказывает совместимость предыдущего клиента.

Целевой процесс генерирует и сверяет привязки до изменения рабочей среды, а затем развёртывает тот же проверенный коммит. Изменение контракта дополнительно проходит [[Разработчику/44-Совместимость-и-миграции-данных|матрицу совместимости]].

## Разрешения

Обычная проверка имеет только чтение. Публикация использует `contents: read` и `packages: write`. Временный `GITHUB_TOKEN` не сохраняется в производственном контейнере.

## Изменение процесса

Рецензирование обязательно для событий запуска, разрешений, передачи секретов, доверия к полученному коду, состава артефактов, срока хранения и правил параллелизма. Привилегированный процесс не должен принимать произвольный недоверенный сценарий.
