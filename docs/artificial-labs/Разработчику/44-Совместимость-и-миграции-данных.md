# Совместимость и миграции данных

Изменение сохранённой структуры — это изменение данных, а не только TypeScript-типа. Оно должно учитывать старый мобильный клиент, сервер, локальную базу, очереди синхронизации, импорт, экспорт и возможность восстановления.

Проект использует несколько независимых версий, но пока не имеет единого журнала миграций и сквозной проверки обновления с предыдущего выпуска.

## Критерии безопасной миграции

- Новый читатель принимает поддерживаемую старую форму.
- Старый читатель либо понимает новую форму, либо отказывает до записи и без повреждения данных.
- Повторный запуск миграции не создаёт дублей и не меняет уже правильный результат.
- Остановленную обработку можно продолжить с сохранённой позиции.
- Старый и новый клиент могут безопасно работать с сервером во время поэтапного обновления.

Одного поля `version` для этих гарантий недостаточно — нужна проверка конкретной пары версий.

## Действующие контракты

| Поверхность | Версия | Текущее поведение |
|---|---|---|
| SQLCipher | Общей версии схемы нет. | Таблицы создаются через `CREATE IF NOT EXISTS`; предметные записи лежат в JSON. Общей системы DDL-миграций нет. |
| Индекс помощника | `agentSearchIndexVersion = 1` | При несовпадении индекс очищается и строится заново. |
| Convex | `convex/schema.ts` | Новые и изменяемые документы проходят серверные валидаторы. Общего журнала дозаполнений нет. |
| JSON-архив | `artificiallabs-health-archive`, версия `1` | Неизвестная версия отклоняется до применения; старая форма дневника имеет адаптер. |
| CSV | Номера версии нет. | Требуется точный заголовок из пяти столбцов. |
| QR-профиль | `artificial-labs.cv-profile/1` | Неизвестная версия отклоняется. |
| StripCV | `schema_version = 1.0` | TypeScript и C++ требуют точного совпадения. |
| Контекст помощника | `2026-08-20-v1` | Сервер принимает только текущую схему и свежий конверт. |
| План наблюдения | Версии правил и каталога от `2026-08-20` | Валидатор требует обе текущие версии. |
| Манифест калибровки | `schemaVersion: 1` | Версия входит в подписываемый материал; нативный клиент его пока не применяет. |

## Локальная база

При открытии создаются `settings`, `records`, `outbox`, `telemetry_outbox` и `agent_search_fts`. В коде нет `PRAGMA user_version`, таблицы миграций и последовательности `ALTER TABLE`.

Новый необязательный JSON-параметр может быть совместимым, если старое значение имеет однозначное поведение. Изменение обязательности, смысла поля, перечисления, даты или единицы требует адаптера чтения.

`mergeRemoteSnapshot()` уже содержит точечные адаптеры старых результатов сканирования. Это подтверждает необходимость миграций, но не образует общую систему.

## Convex и дозаполнение

Сужение `v.union`, удаление необязательного поля или перевод его в обязательное может сломать существующие документы до обновления клиента.

`backfillCatalog` обрабатывает каталог страницами, сохраняет уже заполненные значения и планирует продолжение. Однако для него нет отдельного теста, записи о запуске и завершении, защиты от конкурирующих запусков и обратного преобразования. Наличие функции не подтверждает, что рабочая база уже обработана.

## Импорт и экспорт

JSON версии 1 проверяется до предварительного просмотра. Для большинства сущностей проверяется только базовая форма, `localId`, `updatedAt` и отсутствие локальных адресов. Полной предметной проверки каждого объекта нет.

CSV не версионирован и не защищает значения от интерпретации как формулы табличным редактором. Его следует использовать только с контролируемым источником.

Импорт записывает сущности последовательно, без общей транзакции на весь файл. Ошибка в середине может оставить уже применённую часть. Отдельная запись идемпотентна по паре `(entity, localId)`, но весь импорт не атомарен.

## Как проводить изменение

### 1. Найти всех читателей и писателей

Нужно перечислить текущий и предыдущий мобильный клиент, Convex, административную консоль, импорт, экспорт, фоновые задачи, StripCV, QR, калибровки и аналитику. Для каждого фиксируется поведение со старым, новым и неизвестным значением.

### 2. Сначала расширить чтение

Сначала развёртывается читатель обеих форм, затем писатель новой формы. Сервер не должен требовать новое поле, пока поддерживаемый старый клиент не умеет его отправлять или сервер не может безопасно подставить значение.

### 3. Подготовить восстановление

До массового изменения нужна проверенная копия, способ восстановления и критерий остановки. Для Convex политика резервного копирования, RPO и RTO в репозитории не утверждены; необратимая массовая миграция требует внешнего решения.

### 4. Выполнить ограниченными партиями

Миграция сохраняет позицию, считает просмотренные, изменённые, пропущенные и ошибочные записи и безопасно повторяется. Медицинские значения в журнал не попадают.

### 5. Проверить смешанные версии

- предыдущий клиент пишет в новый сервер;
- новый клиент пишет в переходный сервер;
- предыдущий клиент читает ответ нового сервера;
- старый экспорт проходит новый импорт;
- неизвестная будущая версия отклоняется до записи;
- ошибка не уничтожает локальную очередь.

### 6. Переключить и только затем сузить

Старая форма сохраняется до конца утверждённого окна совместимости. Удалять её можно после подтверждения, что поддерживаемые клиенты больше её не пишут, очереди очищены, дозаполнение завершено, а восстановление проверено.

## Сгенерированный API Convex

`convex/_generated` входит в контракт клиента и функций. Защищённые процессы после `npx convex dev --once` проверяют `git diff --exit-code -- convex/_generated`.

Контроль неполон: обычный CI для запроса на слияние не запускает генерацию, а защищённый процесс проверяет различие уже после отправки функций. Целевой порядок — сначала сгенерировать и проверить тот же коммит, затем развернуть его.

## Возврат версии

Возврат приложения не возвращает данные. Если новый писатель уже сохранил неизвестную старому клиенту форму, старый бинарный файл может усилить инцидент.

План возврата должен ответить, можно ли выключить новый писатель, понимает ли новый читатель обе формы, допустим ли возврат серверных функций и как удерживается локальная очередь. Если обратная совместимость не доказана, выпускается исправленный новый читатель.

## Что сохранять после миграции

- полный SHA и идентификатор миграции;
- старую и новую версии;
- число просмотренных, изменённых, пропущенных и ошибочных объектов;
- начальную и конечную позиции;
- время запуска и завершения;
- результат проверки смешанных версий;
- результат восстановления;
- срок удаления старой формы и остаточные риски.

Фраза «миграция прошла» без этих данных ничего не подтверждает.

## Проверка

```bash
npm test
npm run test:strip-cv
npm run verify
```

Текущие тесты проверяют JSON/CSV, адаптер старого дневника, QR v1 и StripCV `1.0`. Они не покрывают обновление реальной базы предыдущего выпуска, `backfillCatalog`, совместную работу двух версий клиента, частичный импорт и восстановление Convex.
