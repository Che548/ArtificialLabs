# Административная консоль

Пакет `admin/` управляет неперсональными каталогами, калибровками, опубликованными материалами, обезличенными агрегатами, наблюдением и административными членствами.

> [!danger] Медицинские данные пользователей недоступны
> Консоль не предназначена для просмотра учётных записей, профилей, дневника, анализов, сканов, документов и диалогов пользователей.

## Сборка и доставка

`admin/` — отдельное приложение Next.js 16 со статическим экспортом. Команда сборки создаёт `admin/out`. Многоэтапный `Dockerfile` помещает в итоговый образ только этот каталог и конфигурацию nginx.

Expo Web остаётся отдельной демонстрацией для разработки и не входит в публикуемый образ. Итоговый контейнер также не содержит исходный код, Git, `.env` и административные ключи.

Единственный публичный аргумент сборки — `NEXT_PUBLIC_CONVEX_URL`. `CONVEX_SELF_HOSTED_ADMIN_KEY`, `CALIBRATION_SIGNING_PRIVATE_KEY` и `ANALYTICS_HASH_SECRET` остаются за клиентской границей.

## Авторизация

Каждая страница, включая `/kit`, сначала требует вход. Саморегистрация администратора отключена.

Компонент `AdminGate` управляет только отображением. Решение принимает серверная функция `requireAdmin()`, которая проверяет:

1. действующую идентичность Convex Auth;
2. членство текущего пользователя в `adminMemberships`;
3. отсутствие `revokedAt`.

Каждый административный запрос и изменение самостоятельно вызывает `requireAdmin()`. Это относится и к выдаче URL для загрузки файла.

## Первое назначение

Первого администратора назначают внутренней функцией в доверенной среде:

```bash
npx convex run admin:bootstrapByEmail '{"email":"admin@example.org"}' --env-file .env.local
```

Пользователь уже должен существовать. Повторное первичное назначение отклоняется. После него права выдаются и отзываются через защищённые серверные операции и записываются в аудит.

Публичного самоназначения нет. Сервер также запрещает отзыв последнего действующего администратора и удаление его учётной записи до отзыва роли.

## Разделы

| Раздел интерфейса | Назначение |
|---|---|
| `Dashboard` | сводные обезличенные показатели |
| `Test Systems` | справочник тест-систем |
| `Lots` | партии, совместимость и состояние |
| `Calibrations` | версии, согласование, подпись, публикация и возврат |
| `Validation` | результаты проверки калибровок и ресурсов |
| `Content` | версии материалов и публикация |
| `Monitoring` | последние состояния серверной части и прокси сайта Convex |
| `Admin Access` | выдача и отзыв роли |
| `Audit` | журнал административных действий |
| `/kit` | защищённый каталог компонентов интерфейса |

Добавление персональных медицинских данных в любой раздел требует нового решения об архитектуре, целях обработки, угрозах и полномочиях.

## Роли и разделение обязанностей

Серверная модель содержит одну роль — `admin`. Она не разделяет оператора, автора, проверяющего, аудитора и владельца выпуска.

Поля `authorId` и `reviewerId` сохраняются, но код не запрещает их совпадение. Поэтому серверная авторизация действует, а независимое утверждение и периодическая переаттестация остаются внешними требованиями.

## Аудит и пределы чтения

Изменяющие операции принимают `requestId` и записывают:

- инициатора;
- действие;
- тип и идентификатор объекта;
- краткое описание до 500 символов;
- время.

Списки используют курсорную пагинацию. Типовая страница ограничена 50 элементами, а чтение — отдельными пределами строк и байтов.

Аудит не должен содержать секреты, медицинские значения и содержимое загруженного файла. Он также не заменяет внешнюю запись согласования доступа и выпуска.

## Загрузка ресурсов

URL загрузки выдаётся только действующему администратору. После регистрации ресурса сервер проверяет метаданные и запускает внутреннюю валидацию.

Разрешены:

- калибровочный JSON;
- эталонный CSV или JSON;
- изображение для публикуемого материала.

Непригодный ресурс получает состояние `rejected` или удаляется обработчиком. Опубликованные данные ссылаются только на ресурсы в состоянии `validated`.

Проверка типа и размера не доказывает отсутствие персональных данных внутри изображения. Для содержимого требуется отдельная редакционная проверка.

## Локальная проверка

```bash
npm --prefix admin ci
npm --prefix admin run verify
npm test
npm run e2e:web
```

Playwright проверяет защиту `/` и `/kit`, нейтральную ошибку неверного входа и, при наличии защищённых E2E-реквизитов, доступ к административным разделам.

`convex/admin.test.ts` проверяет одноразовое первичное назначение, запрет самоназначения, защиту последнего администратора, аудит, административный каталог и загрузку ресурсов.

## Условия запрета выпуска

Консоль нельзя выпускать, если:

- страница доступна без входа;
- серверная операция полагается только на `AdminGate`;
- в ответе появились персональные медицинские поля;
- секрет попал в публичную переменную или итоговый образ;
- изменяющая операция не записывает безопасный аудит;
- список не ограничен пагинацией и объёмом чтения;
- загруженный непроверенный ресурс можно опубликовать.
