# Классификация ошибок и повторные попытки

Документ определяет устойчивые классы ошибок, интервалы повторов и требования к пользовательскому сообщению.

## Классы

`classifyServiceIssue` возвращает:

| Класс | Сообщение пользователю | Автоматический повтор |
|---|---|---:|
| `offline` | сеть недоступна, изменения сохранены на устройстве | Да |
| `server` | служба временно недоступна, отправка будет повторена | Да |
| `auth` | сеанс истёк, требуется повторный вход | Нет |
| `unknown` | запрос не выполнен, локальные данные не потеряны | Нет |

Серверный классификатор распознаёт ошибки подключения, DNS, сокета, тайм-аута и ответы HTTP 5xx. Класс аутентификации распознаёт отсутствие пользователя, истёкший или неверный токен.

## Интервалы

Транспортные повторы выполняются через 5, 15, 30, 60 и 120 секунд. После достижения максимума задержка не растёт. Восстановление сети запускает немедленную единственную синхронизацию.

## Ошибки без автоматического повтора

Не повторяются автоматически:

- ошибки проверки данных;
- ошибки аутентификации или владельца;
- повреждённый импорт;
- недоверенный QR-профиль;
- неверный запрос StripCV;
- отменённое пользователем разрешение или действие.

## Интерфейс

Сообщение об отсутствии сети и слой неисправности службы не блокируют локальный ввод. Ошибка аутентификации предлагает повторный вход. Пользователю не показываются необработанные стеки и ответы внешнего поставщика.

## Журналирование

Допустимо записывать класс, имя операции, номер попытки, длительность и безопасный идентификатор корреляции. Полезная нагрузка, медицинские значения, пароль, токен, локальный адрес и содержимое файла не журналируются.

## Проверка

Модульные испытания покрывают шаблоны классификации и границы задержек. Интеграционные испытания подтверждают сохранение очереди после отказа сервера, отсутствие повтора аутентификации, немедленную синхронизацию при возвращении сети и единственность выполняемого процесса.
