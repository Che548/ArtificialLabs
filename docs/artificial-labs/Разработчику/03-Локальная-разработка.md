# Локальная разработка

Инструкция описывает воспроизводимую установку, безопасную настройку окружения и запуск всех частей проекта. Команды выполняются из корня репозитория, если не указано иное.

> [!summary] Рекомендуемая среда
> Репозиторий закрепляет Node.js `22.13.1` в `.nvmrc`; `package.json` допускает версии не ниже `20.19.4`. Для одинакового результата разработки и CI используйте закреплённую версию и установку `npm ci`.

## Требования

| Средство | Для чего требуется |
|---|---|
| Node.js `22.13.1` и npm | Expo, TypeScript, Convex, тесты и сборка административного приложения |
| Xcode | сборка и симулятор iOS |
| Android SDK и эмулятор | сборка Android |
| CMake и OpenCV | сборка нативного ядра StripCV |
| Maestro | нативные сквозные сценарии |
| Docker | локальная инфраструктура, если она входит в задачу |
| доступ к выделенному Convex | отправка функций и живые серверные проверки |

Перед изменением кода Expo прочитайте документацию точной версии SDK 54. Правила для NativeWind и Convex перечислены в корневом `AGENTS.md`.

## Установка

```bash
nvm use
npm ci
npm --prefix admin ci
cp .env.example .env.local
```

`npm ci` использует зафиксированный `package-lock.json` и не должен самопроизвольно менять его. Если зависимость действительно изменяется, обновите манифест и lock-файл осознанно, затем выполните проверку состава компонентов.

## Окружение

Минимальный клиентский запуск требует `EXPO_PUBLIC_CONVEX_URL`. Для HTTP-действий используется `EXPO_PUBLIC_CONVEX_SITE_URL`. Команды Convex требуют `CONVEX_SELF_HOSTED_URL` и действующий `CONVEX_SELF_HOSTED_ADMIN_KEY`.

Проверка локального файла:

```bash
git check-ignore .env.local
git status --short
```

Не выводите всё окружение командой `env` и не копируйте `.env.local` в сообщение, задачу или артефакт. Переменная с префиксом `EXPO_PUBLIC_` или `NEXT_PUBLIC_` попадает в клиентский пакет и не может содержать секрет.

Полный реестр приведён в [[Разработчику/29-Переменные-окружения|переменных окружения]].

## Запуск приложения

```bash
npm run start
npm run ios
npm run android
npm run web
```

`npm run start` запускает Metro. Команды `ios` и `android` создают нативную сборку для разработки. `npm run web` открывает демонстрационный режим Expo Web, который не сохраняет медицинские данные.

SQLCipher, SecureStore, камера, StripCV, фоновые задачи и локальные уведомления проверяются только в нативной сборке. Expo Go для этих сценариев недостаточно.

## Convex

| Задача | Команда | Влияние |
|---|---|---|
| режим разработки | `npm run convex:dev` | наблюдает за изменениями и отправляет функции в указанное развёртывание |
| одноразовая отправка | `npm run convex:deploy` | изменяет внешнее состояние выбранного Convex |
| только локальные привязки | `npm run convex:codegen` | обновляет `convex/_generated` без намеренного развёртывания функций |

Перед командой, которая изменяет сервер, проверьте адрес назначения и наличие разрешения на эту среду. После изменения схемы или публичной функции выполните:

```bash
npx convex dev --once --env-file .env.local
git diff -- convex/_generated
```

Сгенерированные привязки должны соответствовать коду. Не исправляйте их вручную.

## Административная консоль

```bash
npm --prefix admin run dev
npm --prefix admin run verify
```

Клиент использует только публичный `NEXT_PUBLIC_CONVEX_URL`. Вход требует существующей учётной записи с действующей записью `adminMemberships`; визуальная проверка в браузере не заменяет `requireAdmin()` на сервере.

Первого администратора создают только доверенной командой начального назначения:

```bash
npx convex run admin:bootstrapByEmail '{"email":"admin@example.invalid"}' --env-file .env.local
```

Подставляйте разрешённый адрес только локально. Не сохраняйте рабочий адрес, ключ или вывод с чувствительными данными в Git.

## Веб-адаптер StripCV

```bash
npm run web:full
```

Команда экспортирует Expo Web, собирает StripCV и запускает локальный сервер. По умолчанию он привязан к `127.0.0.1`. Значение `HOST=0.0.0.0` открывает доступ из сети и требует отдельного анализа угроз; для обычной разработки оно не нужно.

## Обычный цикл изменения

1. Проверьте `git status --short --branch` и отделите пользовательские локальные изменения.
2. Определите затронутые данные, платформы и серверные контракты.
3. Добавьте или обновите ближайший модульный тест.
4. Запустите специализированную проверку изменённого слоя.
5. Выполните базовый набор:

```bash
npm test
npm run verify
```

6. Проверьте итоговое различие и отсутствие секретов.
7. Обновите пользовательскую, техническую и эксплуатационную документацию, если изменился контракт.

## Частые причины сбоя

| Признак | Проверка |
|---|---|
| версия пакета Expo не согласована | `npm run check:expo` |
| ошибка TypeScript | `npm run typecheck` |
| Expo сообщает о неверной конфигурации | `npm run doctor` |
| привязки Convex устарели | `npm run convex:codegen` и проверка различия |
| камера или SQLCipher не работают в Expo Go | создать нативную сборку для разработки |
| StripCV не собирается | проверить CMake, OpenCV и `npm run test:strip-cv` |
| административная страница открывается без данных | проверить вход, роль и доступность Convex, не ослабляя серверный контроль |
