# Матрица приёмочных проверок

Матрица определяет минимальную проверку для каждой функциональной области. Набор выбирается по фактическому влиянию изменения, а не по названию файла.

> [!important] Общее правило
> Успешная сборка не подтверждает работу без сети, серверную принадлежность данных и медицинскую безопасность. Эти свойства проверяются отдельными сценариями.

## Пользовательское приложение

| Область | Ожидаемое поведение | Обязательная проверка | Текущее покрытие |
|---|---|---|---|
| Регистрация и вход | вход по электронной почте, безопасная ошибка, повторный вход, отсутствие саморегистрации администратора | модульные, живой серверный E2E, нативный E2E, Playwright для консоли | частично автоматизировано |
| Начальная настройка | цель и профиль сохраняются; повторный запуск не возвращает пройденные шаги | Maestro на iOS и Android | есть основные сценарии |
| Профиль | цель меняет главную панель; даты и числовые пределы проверяются; карточки можно изменить и удалить | модульные вычисления и нативный сценарий | предметное покрытие неполно |
| Дневник | запись сохраняется локально без сети; дата и категории не смешиваются; удаление не теряет соседние записи | `journal-options`, `product-insights`, Maestro без сети и после подключения | вычисления покрыты; полный ввод — нативным E2E |
| Календарь цикла | отметки менструации группируются; расчёт устойчив к часовому поясу; недостаток данных показан честно | `cycle-insights.test.ts`, `health-insights.test.ts`, нативная проверка дат | модульное покрытие есть |
| Анализы и документы | структурированная запись сохраняется; исходный файл остаётся локальным | модульные испытания передачи данных и нативный выбор файла | частично автоматизировано |
| Сканирование | камера или импорт, оценка качества, коррекция, подтверждение пользователя и история | CTest, проверка запуска StripCV, один тестовый снимок на iOS и Android | основной нативный сценарий есть |
| Уведомления | локальный режим работает без реквизитов удалённой доставки; разрешение и категории соблюдаются | `notification-schedule.test.ts`, нативный E2E | удалённая доставка требует внешней настройки |
| Импорт и экспорт | предварительный просмотр, версии формата, отсутствие локальных URI, повторное применение без дублей | `data-transfer.test.ts`, нативный выбор и применение файла | модульное покрытие есть; матрица старых версий неполна |
| Удаление аккаунта | запрос, 30-дневная блокировка, восстановление и окончательная очистка | серверный и нативный E2E | основной серверный путь есть |

## Синхронизация и серверные функции

| Область | Ожидаемое поведение | Обязательная проверка | Текущее покрытие |
|---|---|---|---|
| Локальная синхронизация | отдельное включение, исходящая очередь, ограниченный повтор и запуск после возвращения сети | `cloud-sync.test.ts`, `sync-policy.test.ts`, Maestro без сети и после подключения | клиентская часть покрыта лучше серверного запрета |
| Принадлежность | второй пользователь не читает и не меняет чужой профиль | `convex/health.test.ts`, `tests/e2e/backend.live.ts` | основные медицинские функции покрыты |
| Публичный API | каждая функция имеет класс доступа, валидаторы, пределы, ошибки и правило повтора | положительный сценарий, без входа, второй пользователь, обычный пользователь, отозванная роль, граница квоты | полного перебора 61 функции нет |
| Схема и миграции | старый и новый клиент понимают переходную форму; повтор миграции безопасен | образцы предыдущих версий, смешанные клиенты, частичный сбой, восстановление | общего набора нет |
| `convex/_generated` | привязки соответствуют развёртываемым функциям до изменения среды | генерация и проверка Git-различия | защищённые задания проверяют после отправки функций |

## Медицинская логика и ИИ

| Область | Ожидаемое поведение | Обязательная проверка | Текущее покрытие |
|---|---|---|---|
| StripCV | источник, версия алгоритма, признаки качества и подтверждение пользователя сохраняются раздельно | CTest, проверка запуска, нативный E2E, отрицательные снимки | основная техническая цепочка есть |
| План наблюдения | один активный пункт на ключ, допустимые переходы, атомарная запись, честное основание и безопасный резервный вариант | таблица переходов, конфликт, повтор, частичный сбой, старые версии, медицинская проверка | вычисления интерфейса и поставщик покрыты; `care-plan` и `agentPlan` — нет |
| Обычный ИИ-диалог | отдельное согласие, флаг по умолчанию выключен, ограниченный текст, квоты и безопасные ошибки | `convex/chat.test.ts`, испытание поставщика в защищённой среде | серверная граница покрыта частично |
| Расширенный помощник | отдельное согласие, разрешённые категории, одноразовые инструменты, отсутствие смешения пользователей | внедрение инструкций, подмена источника, повтор продолжения, второй пользователь, опасный медицинский ответ | полного обязательного набора нет |
| Автоматическая проверка плана | независимый флаг, отдельная квота, нерегулярный фон, запрет опасного текущего пункта | интерактивный и плановый запуск, конкурентность, отзыв, выключение, безопасный резервный план | поставщик покрыт; сквозная автоматизация — нет |

ИИ-режим без полного допуска остаётся выключенным. Наличие запасного плана не заменяет медицинскую оценку.

## Веб и администрирование

| Область | Ожидаемое поведение | Обязательная проверка | Текущее покрытие |
|---|---|---|---|
| Expo Web | демонстрация не создаёт медицинские записи и не запрашивает уведомления | экспорт и проверка безопасных `.web`-адаптеров | входит в `npm run verify` |
| Административная консоль | каждая страница требует вход; сервер повторно проверяет `admin`; персональных таблиц нет | `convex/admin.test.ts`, Playwright, проверка ограниченных ответов | основные сценарии есть |
| Каталог и калибровки | публикация только проверенного ресурса; подпись и откат записываются | административные испытания, подмена ресурса, ошибка подписи | серверная часть частична; клиентская проверка подписи не интегрирована |
| Телеметрия | подробные события требуют согласия; поля ограничены; сроки удаления применяются | `convex/telemetry.test.ts`, проверка отказа после отзыва | подробный поток покрыт; `heartbeat` живёт отдельно от согласия |

## Выпуск и эксплуатация

| Область | Ожидаемое поведение | Обязательная проверка | Текущее покрытие |
|---|---|---|---|
| Веб-образ | содержит только `admin/out` и nginx; не содержит секреты и исходники | сборка, проверка состава, `/health`, Playwright | автоматизирована сборка; состав требует отдельной проверки |
| GitHub Actions | запрос на слияние не получает производственные секреты; публикация связана с SHA | ревизия событий, разрешений, секретов и меток | граница событий реализована |
| Наблюдение | сигнал свежий, безопасный и приводит к действию; отказ монитора различим | тайм-аут, устаревание, потеря наблюдения, доставка оповещения | внешнего сквозного монитора и SLO нет |
| Возврат | выбран точный артефакт; схема и данные совместимы | возврат по дайджесту, проверка данных, входа и критических функций | учебное восстановление не подтверждено |

## Сквозные проверки

Для каждой изменённой области подтверждают:

1. поведение без сети;
2. второго пользователя и недостаточные полномочия;
3. границы размера и частоты;
4. повтор после временной ошибки;
5. выключенное состояние отложенной функции;
6. отсутствие секретов и медицинских данных в журналах;
7. совместимость со старым сохранённым состоянием;
8. очистку и остаточные данные;
9. точный коммит и платформу результата.

## Устройства и артефакты

Нативное изменение проверяют как минимум на iOS и Android. Изменение плагина, SQLCipher, камеры, уведомлений или StripCV требует чистой нативной сборки; Expo Go недостаточен.

Артефакты содержат только обезличенные результаты. В них не помещают токены, пароли, медицинские изображения, полные журналы и рабочие данные. Блокировка средой регистрируется как невыполненная проверка, а не как успех продукта.

## Допуск

Для каждой затронутой строки нужен успешный результат или утверждённое исключение с владельцем и сроком. Инварианты локальной записи, принадлежности, конфиденциальности и обязательного подтверждения медицинского значения исключениями не снимаются.
