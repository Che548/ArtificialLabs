# Развёртывание и выпуск

Документ описывает публикацию веб-образа, развёртывание Convex и обязательные проверки нативного выпуска.


> [!summary] Кратко
> Защищённая автоматизация сначала проверяет точный коммит и развёртывает функции Convex, затем публикует минимальный веб-образ. Ручной запуск для другой ветви также изменяет `latest` и поэтому считается рабочим действием с теми же требованиями к утверждению и откату.

## Веб-образ

Многоэтапный `Dockerfile` устанавливает корневые зависимости и зависимости `admin/`, создаёт статический `admin/out` и копирует в конечный контейнер nginx только этот экспорт и конфигурацию веб-сервера. Expo `dist` не входит в рабочий образ. Конечный контейнер не должен содержать исходный код, метаданные Git, файлы окружения и административные реквизиты.

Nginx предоставляет резервный маршрут одностраничного приложения и `/health`. `infra/web/docker-compose.yml` запускает контейнер `artificiallabs_web` и отдельный Watchtower, ограниченный меткой.

## Идентичность и продвижение версии

Каждый публикуемый образ связывается с полным Git SHA и неизменяемым дайджестом контейнера. Теги ветви и `latest` удобны для продвижения, но не идентифицируют точный артефакт.

| Событие | Результат | Эксплуатационное значение |
|---|---|---|
| отправка в `main` | автоматическое развёртывание Convex и публикация образа | рабочее продвижение проверенного коммита |
| ручной запуск для выбранной ветви | развёртывание выбранной ревизии и обновление `latest` | рабочее действие, требующее явного решения о выпуске |
| повторный запуск прежнего коммита | новая запись автоматизации для той же ревизии | не заменяет проверку фактического дайджеста и среды |

Возврат версии выполняется на известный исправный дайджест, а не на предположение о содержимом `latest`. Откат функций Convex отдельно проверяется на совместимость схемы и данных.

## Защищённая автоматизация

Последовательность GitHub Actions:

1. получение исходного кода и настройка Node.js;
2. установка корневых зависимостей и зависимостей `admin/`, затем `npm run verify`;
3. развёртывание функций Convex с секретом репозитория;
4. проверка `convex/_generated`;
5. сборка и публикация Docker-образа;
6. присвоение меток SHA, ветви и `latest`.

Отправка в `main` запускает процесс автоматически. Для другой ветви используется ручной **Build and Publish Web Image**. Ручной запуск также обновляет `latest` и считается производственным действием.

Автоматизация с административным ключом не должна запускаться событием `pull_request`. В аргумент сборки Docker передаётся только публичный `NEXT_PUBLIC_CONVEX_URL`. Передача `CONVEX_SELF_HOSTED_ADMIN_KEY`, `CALIBRATION_SIGNING_PRIVATE_KEY` или `ANALYTICS_HASH_SECRET` запрещена.

## Выполнение на узле

Образ `ghcr.io/che548/artificiallabs` доступен для публичного чтения. Watchtower обновляет только контейнер с разрешающей меткой. Сохранять токен GHCR на узле не требуется.

## Convex

`infra/convex/docker-compose.yml` запускает сервер и панель с постоянным томом данных. Проверка состояния обращается к `/version`. Секрет экземпляра и публичные адреса задаются вне Git.

## Нативный выпуск

SQLCipher, SecureStore, камера и StripCV требуют подписанной нативной сборки. Проверяются разрешения, локальная запись без сети, восстановление синхронизации, ручное подтверждение скана и работа только с локальными уведомлениями при отсутствии реквизитов удалённой доставки.

## Решение перед выпуском

До продвижения версии запись выпуска должна связать точный коммит, дайджест образа, затронутые платформы, результаты проверок, известные ограничения и предыдущий исправный артефакт. Ручное обновление `latest` не освобождает от этого требования.

Минимальный контрольный список:

- `npm run verify`;
- `npm run test:strip-cv` при изменении CV;
- соответствующие E2E-наборы;
- отсутствие неожиданного изменения привязок;
- отсутствие секретов и исходных файлов в образе;
- работоспособность `/health`;
- известная предыдущая исправная версия;
- отсутствие обещаний отложенных функций.
