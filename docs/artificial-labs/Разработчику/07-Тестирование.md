# Тестирование

Проверки проекта подтверждают технический контракт на нескольких уровнях: чистые вычисления, серверные функции, сборку двух веб-приложений, нативное поведение и договорённости с работающим выделенным Convex. Ни одна отдельная команда не заменяет остальные уровни.

> [!summary] Минимум для обычного изменения
> Запустите `npm test` и `npm run verify`, а затем добавьте специализированную проверку затронутого слоя. Для изменения SQLCipher, камеры, StripCV или нативного модуля нужна сборка для разработки или выпуска: Expo Go недостаточно.

## Уровни проверки

| Уровень | Что подтверждает | Основная команда |
|---|---|---|
| Модульный | детерминированные правила без внешней среды | `npm test` |
| Серверный в памяти | доступ, владение, ограничения и сроки хранения Convex | `npm test` |
| Статический и сборочный | версии Expo, TypeScript, Expo Doctor, экспорт Expo Web и административного приложения | `npm run verify` |
| Нативный C++ | интерфейс и обработка StripCV | `npm run test:strip-cv` |
| Живой серверный E2E | контракт с выделенным Auth и Convex | `npm run e2e:backend` |
| Веб-E2E | защищённый опубликованный административный интерфейс | `npm run e2e:web` |
| Нативный E2E | сценарии iOS и Android в Maestro | `npm run e2e:native` |
| Покрытие возможностей | целостность зарегистрированной матрицы E2E | `npm run e2e:coverage` |

## Модульный и серверный набор

```bash
npm test
```

Команда сначала запускает тесты Node.js через `tsx --test`, затем проверки Convex и провайдера ИИ через Vitest.

### Прикладные правила

| Область | Что проверяется |
|---|---|
| Сканирование | QR-профили, интерпретация, геометрия наложения и веб-запрос StripCV |
| Сеанс | восстановление аутентификации и безопасное завершение состояния |
| Диалог | порядок и предел истории, удаление, состояние генерации и безопасный Markdown |
| Синхронизация | исходящая очередь, политика согласия, транспортные ошибки и восстановление |
| Перенос данных | формат, очистка локальных адресов и идемпотентный импорт |
| Уведомления | формирование локального расписания |
| Цикл и дневник | календарные границы, фактические периоды, задержка и взаимоисключающие ответы |
| Показатели здоровья | сегменты цикла и интенсивность только из явно введённых данных |
| Продуктовые показатели | заполненность дневника, выполнение плана и неделя беременности без вымышленных значений |
| Прокси E2E | ограниченный контракт доступа сквозного исполнителя к Convex |

### Серверные правила

Vitest проверяет владение медицинскими данными, диалог, административный доступ, телеметрию и адаптер Yandex AI. Для плана наблюдения отдельно подтверждаются:

- раздельные лимиты интерактивной и плановой проверки;
- отсутствие встроенных повторов и журналирования содержимого в клиенте провайдера;
- текстовый запрос с серверной инструкцией;
- безопасное преобразование отказов и ошибок без возврата тела ответа поставщика;
- отклонение рекомендаций, основанных только на неподходящих данных дневника;
- повторная генерация неверно сформированного плана;
- переход к консервативному плану `server-catalog` после двух неуспешных генераций.

Эти тесты подтверждают программные ограничения, но не клиническую пригодность рекомендаций.

## Проверка проекта и сборки

```bash
npm run verify
```

Команда выполняет проверки в следующем порядке:

1. `expo install --check` — согласованность версий пакетов Expo.
2. `tsc --noEmit` — типы основного приложения.
3. `expo-doctor` — состояние проекта Expo.
4. экспорт Expo Web в `dist/`.
5. `npm --prefix admin run verify` — типы и статический экспорт административной консоли.

Успешная сборка показывает, что артефакт можно получить, но не доказывает правильность доступа, хранения или медицинской интерпретации.

## StripCV

```bash
npm run test:strip-cv
```

Команда собирает нативное ядро, запускает CTest, выполняет дымовую проверку JavaScript-обёртки и проверку локального сервера. При изменении камеры или нативных мостов дополнительно нужна реальная сборка для разработки на обеих платформах.

Медицинский образец для проверки передаётся только локальным путём. Он не включается в Git и не публикуется как артефакт CI.

## Живой серверный E2E

```bash
npm run e2e:backend
```

Исполнитель создаёт одноразовые учётные записи, проверяет живой контракт Auth и Convex и всегда выполняет точное административное удаление. Реквизиты, пароли и результаты находятся только в игнорируемом `output/e2e/`.

Эта команда обращается к выделенному развёртыванию. Перед запуском необходимо убедиться, что используется разрешённая среда и что административный ключ не попадёт в вывод терминала.

## Веб-E2E

```bash
npm run e2e:web
```

Playwright проверяет опубликованную административную консоль: защиту `/` и `/kit`, нейтральную ошибку входа и, при наличии специально разрешённых реквизитов, доступ к предусмотренным разделам. Браузерный тест не получает административный ключ Convex CLI; роль подтверждается через Convex Auth и `adminMemberships`.

## Нативный E2E

```bash
npm run e2e:native
```

Maestro выполняет сценарии iOS и Android: вход, начальную настройку, основные экраны, работу без сети, восстановление соединения, синхронизацию, перенос данных и жизненный цикл учётной записи.

Для одного и того же локального изображения на обоих симуляторах задаётся `E2E_SCAN_FIXTURE_SOURCE`. Исполнитель копирует файл с ограниченными правами и удаляет временные копии при очистке. Медицинские изображения нельзя помещать в репозиторий или артефакты CI.

## Перед выпуском

| Изменение | Обязательные дополнительные проверки |
|---|---|
| Только TypeScript-интерфейс | `npm test`, `npm run verify`, соответствующий Maestro-сценарий |
| Серверная схема или функция | `npm test`, `npm run e2e:backend`, миграционный анализ |
| Административная консоль | `npm --prefix admin ci`, `npm --prefix admin run verify`, `npm run e2e:web` |
| SQLCipher или локальные файлы | нативная сборка, сценарии без сети и переноса, проверка обновления БД |
| Камера или StripCV | `npm run test:strip-cv`, сборки iOS и Android для разработки, локальный образец |
| ИИ или план наблюдения | `npm test`, отрицательные проверки согласия, лимитов, структуры ответа и аварийного режима |
| Рабочий процесс выпуска | проверка разрешений, событий запуска, секретов и состава конечного образа |

Производственный файл `.github/workflows/e2e-live.yml` должен оставаться доступным только для ручного запуска. Административный ключ не передаётся заданиям pull request или недоверенному коду.

> [!warning] Ограничение матрицы покрытия
> `npm run e2e:coverage` проверяет зарегистрированные 21 возможности, но текущий файл покрытия ещё не включает все более новые функции административной консоли, телеметрии, вычислений цикла и ИИ-плана. Успешная команда не закрывает эти пробелы автоматически.
