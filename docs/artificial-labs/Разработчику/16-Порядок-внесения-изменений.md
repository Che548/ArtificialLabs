# Порядок внесения изменений

Документ задаёт последовательность безопасной работы в общей рабочей копии.

## Перед изменением

1. Прочитать `AGENTS.md`.
2. Выполнить `git status --short --branch`.
3. Отделить пользовательские изменения от текущей задачи.
4. Определить затрагиваемые функции, платформы и категории данных.
5. Найти существующую реализацию через `rg` и `rg --files`.
6. Прочитать обязательную версионную документацию Expo, NativeWind или Convex.

Не сбрасывайте и не перезаписывайте чужие изменения. Не расширяйте состав задачи без необходимости.

## Реализация

- сохраняйте локальное первичное хранение и серверную проверку владельца;
- изменяйте минимальный ответственный слой;
- обновляйте типы, схему и привязки штатными средствами;
- добавляйте регрессионную проверку для новой политики;
- не маскируйте ошибки аутентификации и проверки данных транспортным повтором;
- не превращайте экспериментальный код в продуктовое обещание;
- обновляйте пользовательскую инструкцию только при изменении сценария;
- обновляйте техническое описание при изменении контракта или операции.

## Проверка

```bash
npm test
npm run verify
git diff --check
```

По составу изменения дополнительно выполняются CTest и проверка StripCV, одноразовое развёртывание или генерация Convex, серверное E2E, Playwright и Maestro.

## Контроль перед рецензированием

Проверьте поведение без сети, классификацию данных, экспорт и журналирование, владельца на сервере, веб-границу, необходимость нативной сборки, состояние отложенных функций, очистку, возможность возврата и соответствие испытания изменению.

## Работа с Git

Не добавляйте игнорируемые файлы окружения, сборки, артефакты E2E и локальное хранилище документации. Перед фиксацией просмотрите подготовленные изменения. Фиксация и публикация выполняются только по прямому запросу.
