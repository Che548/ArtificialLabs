# StripCV и обработка изображений тестов

Документ описывает отслеживаемый производственный путь анализа изображения. Неотслеживаемые наборы данных, эксперименты и локальные программы оценки не входят в документацию.

## Слои

- `services/scanning/` — прикладное управление, встроенные профили, проверка QR-кода, геометрия наложения, история и интерпретация;
- `modules/strip-cv/src/` — типизированный интерфейс Expo;
- `modules/strip-cv/ios/` и `android/` — платформенные мосты;
- `modules/strip-cv/native/` — переносимое ядро C++ и OpenCV.

## Контракт выполнения

`analyzeStripAsync` принимает локальный адрес изображения, профиль теста, сведения калибровки, необязательные исправления углов и параметры качества. Результат соответствует схеме `1.0`. При отсутствии нативного модуля возвращается явная ошибка о необходимости сборки разработки.

## Доверие к профилю

Встроенный профиль называется `handled-paper-two-line-strip` и имеет версию `1.0-observed-real-layout`. Проверенного биологического порога нет. Неподписанный QR-код не может заменить алгоритм, калибровку или порог. До внедрения подписанных профилей принимается только точное соответствие встроенному профилю без порога.

## Безопасность результата

В локальной записи сохраняются источник, версия алгоритма и калибровки, признаки качества, отношение сигналов, числовая уверенность, состояние анализа, происхождение результата и подтверждение пользователя.

Отсутствующая контрольная линия, слабый сигнал, пятна, неоднозначность и недостаточная геометрия не должны превращаться в автоматически пригодный результат. StripCV не формирует диагноз.

## Нативные реализации

Android использует OpenCV 5 через AAR и Prefab, CMake 3.22.1 и C++17. iOS использует `OpenCV-Dynamic-Framework` 4.10, статический модуль Expo и C++17. Изменение моста или зависимости требует новой нативной сборки на обеих платформах.

## Проверка

```bash
npm run build:strip-cv
ctest --test-dir web-build/stripcv-native --output-on-failure
npm run test:strip-cv
```

Исходные медицинские изображения запрещено добавлять в Git и публиковать как артефакты.
