# Проверка готовности выпуска

Решение о выпуске принимается для точного коммита, конкретных платформ и определённого набора изменений. Успешное задание CI подтверждает только выполненные в нём проверки и не заменяет оценку данных, безопасности, восстановления и эксплуатации.

> [!important] Условие допуска
> До выпуска должны быть известны состав изменения, обязательные проверки, открытые ограничения, предыдущий исправный артефакт и роль, принимающая остаточный риск.

## Паспорт выпуска

| Поле | Обязательное значение |
|---|---|
| Идентификатор | уникальное устойчивое значение |
| Коммит | полный Git SHA из разрешённой ветви |
| Состав | выбранные отслеживаемые изменения и затронутые контракты |
| Платформы | iOS, Android, Expo Web, административный веб-интерфейс, Convex |
| Среда сборки | версия Node.js, номер сборки и основные инструменты |
| Серверная часть | развёртывание Convex и состояние `convex/_generated` |
| Веб-образ | адрес реестра, неизменяемый дайджест и связанные теги |
| Нативные артефакты | идентификаторы сборок iOS и Android и среда подписи |
| Предыдущая исправная версия | проверенный коммит, дайджест образа или нативная сборка |
| Решение | разрешён, разрешён с условиями или запрещён |
| Ответственная роль | кто и когда принял решение |

Тег `latest` и имя ветви изменяемы. Они не идентифицируют выпущенный артефакт без полного коммита или дайджеста.

## Определение области проверки

В паспорте отмечают все затронутые области:

- пользовательские сценарии и тексты;
- локальная медицинская запись и исходящая очередь;
- схема Convex, миграции, синхронизация и удаление;
- публичные функции, ошибки, лимиты и совместимость клиентов;
- вход, принадлежность данных и административные права;
- StripCV, QR-профили, каталог и калибровки;
- уведомления и разрешения устройства;
- телеметрия, сроки хранения и согласия;
- ИИ-поставщик, модель, контекст, инструменты, план и автоматизация;
- Expo Web и административная консоль;
- зависимости, сборка, образы и GitHub Actions;
- развёртывание, наблюдение, поддержка и восстановление;
- документация.

Обязательные проверки определяются фактическим влиянием, а не числом изменённых файлов. Неотмеченная область не освобождает от проверки, если изменение влияет на неё косвенно.

## Базовый набор команд

Для чистого состояния выбранного коммита выполняют:

```bash
npm ci
npm --prefix admin ci
npm test
npm run test:strip-cv
npm run e2e:coverage
npm run verify
```

`npm run verify` проверяет совместимость Expo, TypeScript, Expo Doctor, экспорт Expo Web и сборку административной консоли. Он не запускает `npm test`, нативные E2E и живые испытания Convex.

Живые и нативные испытания запускают отдельно, если область изменения их требует:

```bash
npm run e2e:backend
npm run e2e:web
npm run e2e:native
```

Рабочие ключи и медицинские тестовые материалы используют только в разрешённой среде. Пропущенную обязательную проверку регистрируют как исключение, а не как успешный результат.

## Матрица допуска

| Область | Что должно быть подтверждено |
|---|---|
| Git | проверено выбранное различие; Vault, секреты и невыбранные файлы не входят в коммит |
| Модульные испытания | полный успешный результат `npm test` |
| Проект | успешный `npm run verify` на чистой установке |
| Матрица E2E | `npm run e2e:coverage`; отложенные и непокрытые сценарии объяснены |
| Нативные платформы | iOS и Android проверены после изменения хранилища, камеры, уведомлений или нативного модуля |
| Convex | схема, Auth и серверные функции проверены модульно и, при необходимости, в разрешённой живой среде |
| Административная консоль | серверная роль, ограниченные запросы и защищённый Playwright |
| StripCV | сборка, CTest, проверка запуска и одинаковый тестовый материал на обеих платформах |
| Данные | классификация, миграция, синхронизация, экспорт, удаление и остаточные хранилища |
| API | класс доступа, отрицательные сценарии, ошибки, пределы, повтор, codegen и старый клиент |
| ИИ | режим выключен либо выполнен отдельный допуск поставщика, модели, согласия, контекста, безопасности и эксплуатации |
| Надёжность | свежие сигналы, безопасное ограничение функций, доставка оповещения и способ возврата |
| Цепочка поставки | изменение lock-файла, SBOM, лицензии, уязвимости и происхождение образа |
| Документация | обновлены пользовательские, технические и эксплуатационные страницы |

## Обязательные свойства

Нарушение любого пункта запрещает выпуск независимо от остальных результатов.

### Данные и приватность

1. Завершённая локальная запись не зависит от доступности сети.
2. Исходные медицинские файлы не передаются в Convex.
3. Персональная функция проверяет владельца на сервере.
4. Подробная телеметрия не принимается без действующего согласия.
5. Публичный каталог не содержит персональных данных.
6. Удаление описывает конкретные хранилища, остатки и срок исполнения.
7. Производное медицинское значение сохраняет источник, версию преобразования, признаки качества и требуемое подтверждение.

### Полномочия и секреты

1. Административная функция вызывает `requireAdmin()`.
2. Изменение привилегий имеет аудит и определённый порядок отзыва.
3. Привилегированное задание не запускается для недоверенного события.
4. Секреты отсутствуют в Git, аргументах сборки, образах, журналах и артефактах.
5. Рабочий веб-образ содержит только `admin/out` и конфигурацию nginx.

### Совместимость и восстановление

1. Новая форма данных не записывается, пока поддерживаемые читатели её не понимают.
2. Необратимая миграция не начинается без проверенного восстановления.
3. Новая публичная функция имеет класс доступа, ограниченный контракт и отрицательные испытания.
4. Известен безопасный возврат, не требующий удаления рабочих данных.
5. Локальная проверка процесса не выдаётся за пользовательскую доступность сервиса.

### Медицинская безопасность и ИИ

1. Результат StripCV не называется диагнозом и требует подтверждения пользователя.
2. ИИ не обрабатывает данные без отдельного согласия и включённого серверного режима.
3. Режим без полного пакета допуска остаётся выключенным.
4. Детерминированный резервный план не описывается как медицински утверждённая рекомендация.
5. Разрешение ОС, вход и общий серверный флаг не заменяют отдельную цель обработки и отзыв.

## Исключения

Если обязательную проверку нельзя выполнить, запись исключения содержит:

| Поле | Содержание |
|---|---|
| Идентификатор | устойчивый ID исключения |
| Пропущенная проверка | команда, сценарий или `AL-CTRL-*` |
| Причина | фактическое препятствие |
| Влияние | платформы, пользователи и категории данных |
| Риск | возможный ущерб и условия его возникновения |
| Компенсирующая мера | временное уменьшение вероятности или ущерба |
| Владелец | ответственная роль |
| Срок | дата обязательного пересмотра |
| Условие закрытия | конкретная проверка, исправление или внешнее решение |
| Утверждение | роль, принявшая остаточный риск |

Исключение не допускается для раскрытия секрета, доступа к чужим данным, потери завершённой локальной записи, обхода серверной авторизации и обхода обязательного подтверждения медицинского результата.

## Решение

- **Разрешён** — обязательные проверки выполнены; открытые ограничения не затрагивают состав выпуска.
- **Разрешён с условиями** — ограниченное исключение имеет владельца, срок и компенсирующую меру.
- **Запрещён** — нарушено обязательное свойство, отсутствует необходимая проверка, неизвестен безопасный возврат или риск не принят ответственной ролью.

Решение содержит краткое обоснование и не исправляется задним числом. Новые сведения оформляют новой версией записи с собственной датой и итогом.

## Безопасность пакета выпуска

В пакет нельзя включать:

- `.env` и значения секретных переменных;
- административные ключи, ключи подписи и секреты HMAC;
- пароли, токены входа и токены удалённой доставки;
- рабочие медицинские материалы;
- снимки экрана с персональными данными;
- полные необработанные журналы;
- содержимое запросов и ответов ИИ.

Для защищённых систем сохраняют идентификатор записи или запуска, а не копию чувствительного содержимого. Срок хранения пакета утверждает внешняя политика. Настроенные в репозитории 14 дней относятся только к артефактам живых E2E, а не ко всей документации выпуска.
