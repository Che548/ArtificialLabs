# Зависимости и нативные сборки

Документ фиксирует базовые версии и признаки изменения нативного графа зависимостей.


> [!summary] Кратко
> Изменение плагина, разрешения, нативного моста, podspec, Gradle или CMake требует новой нативной сборки. Обычное изменение TypeScript без изменения нативного графа обычно не требует её.

## Базовые версии

| Компонент | Версия |
|---|---|
| Node.js | `>=20.19.4` |
| Expo | SDK 54, пакет `~54.0.37` |
| React Native | `0.81.5` |
| React | `19.1.0` |
| TypeScript | `~5.9.2` |
| NativeWind | `4.2.6` |
| Convex | `^1.42.3` |
| OpenAI JS | `6.49.0` |
| Vitest | `4.1.10` |
| Playwright | `^1.62.1` |

Совместимость пакетов Expo проверяется командой `npm run check:expo`. Произвольное повышение версии без рекомендаций Expo запрещено.

## Когда требуется новая нативная сборка

- изменение плагинов или разрешений `app.json`;
- изменение настройки SQLCipher или SecureStore;
- изменение камеры, выбора изображений или уведомлений;
- изменение конфигурации модуля Expo;
- изменение Swift, Kotlin, Objective-C++, JNI или моста C++;
- изменение podspec, Gradle или CMake;
- добавление нативного пакета.

Изменение только JavaScript или TypeScript обычно не требует пересборки клиента разработки, если нативный граф не изменился.

## Зависимости StripCV

Локальная сборка ищет OpenCV через `OpenCV_DIR`, `OPENCV_DIR`, пути CMake и стандартные каталоги системы. iOS использует OpenCV 4.10, Android — OpenCV 5 через AAR и Prefab. Переносимое ядро не должно включать локальные служебные программы в мобильную цель.

## Конфигурация Expo

`app.json` подключает шрифты, маршрутизацию, уведомления, браузер, выбор изображений, камеру, управление фокусом и экспозицией, SQLCipher SQLite, SecureStore, ресурсы и фоновую задачу. Изменение разрешений проверяется в сгенерированных проектах и на устройстве или эмуляторе.

## Обновление

1. Прочитать документацию текущего SDK или руководство миграции.
2. Обновить пакет рекомендуемой командой Expo.
3. Выполнить `npm install`.
4. Запустить `npm run check:expo` и `npm run doctor`.
5. При необходимости пересоздать и собрать нативные проекты.
6. Выполнить проверку типов, модульные и нативные испытания.
7. Просмотреть изменения Pod, Gradle и CMake.
8. Обновить матрицу версий и описание выпуска.
