# Термины и сокращения

Глоссарий определяет значения терминов, используемых в пользовательской и технической документации.

| Термин | Определение |
|---|---|
| Локальное первичное хранение | подход, при котором запись сначала надёжно сохраняется на устройстве и не зависит от доступности сервера |
| Структурированные данные | отдельные поля профиля, дневника, анализов, сканирований и напоминаний без содержимого исходных файлов |
| Исходный файл | фотография теста или лабораторный документ в локальном хранилище приложения |
| Облачная синхронизация | передача структурированных данных, включаемая отдельным согласием для устройства |
| Исходящая очередь | локальная очередь изменений, ожидающих первой или повторной отправки; в коде называется `outbox` |
| StripCV | нативный модуль компьютерного зрения для анализа изображения тест-полоски |
| Признаки качества | наблюдаемые ограничения изображения, требующие повторной съёмки или ручной проверки |
| Отношение сигналов | числовая характеристика изображения, которая сама по себе не является диагнозом |
| Ручное подтверждение | явный выбор окончательного результата пользователем |
| Нативная сборка | сборка разработки или выпуска для iOS либо Android с нативными модулями |
| Демонстрация только для чтения | веб-режим без записи персональных медицинских данных |
| Convex | серверная платформа для аутентификации и необязательной синхронизации |
| Одноразовая тестовая учётная запись | временная запись для сквозных испытаний, удаляемая после завершения проверки |
| Состав изменений | отслеживаемые изменения, выбранные для учёта в текущей документации |
| Отложенная возможность | подготовленная, но не включённая в поддерживаемый пользовательский контракт функция |
| E2E | сквозное испытание пользовательского сценария через несколько компонентов системы |
| Контроль | организационная или техническая мера, уменьшающая вероятность либо последствия риска |
| Результат проверки меры | проверяемый артефакт, подтверждающий проектирование или фактическую работу контроля |
| Модель угроз | систематизированное описание активов, границ доверия, угроз, действующих мер и остаточных рисков |
| Остаточный риск | риск, сохраняющийся после применения действующих мер контроля |
| RACI | матрица распределения ролей: исполнитель, ответственный за результат, консультируемый и информируемый |
| SBOM | машиночитаемый перечень программных компонентов, версий и происхождения зависимостей |
| RPO | максимально допустимый объём потери данных, выраженный как период времени |
| RTO | максимально допустимое время восстановления сервиса или процесса |
| Неизменяемая ссылка | ссылка на артефакт или зависимость по криптографическому дайджесту либо полному идентификатору ревизии |
| Дайджест | криптографический идентификатор содержимого; изменение содержимого приводит к другому значению |
| Проверка допуска | обязательная проверка, без успешного результата которой изменение не разрешается к выпуску |
| Пакет подтверждений выпуска | связанный с точным коммитом набор результатов испытаний, решений, ограничений и данных об артефактах |
| Аварийный доступ | заранее утверждённый ограниченный способ восстановить административное управление при недоступности штатных учётных записей |
| Карточка обращения | минимальная структурированная запись о симптоме, версии, влиянии, безопасных проверках и владельце следующего действия |
| Эскалация | передача обращения роли с достаточными полномочиями или компетенцией из-за риска, масштаба либо отсутствия безопасного решения |
| Приоритет P0—P3 | классификация возможного влияния; сама по себе не задаёт числовое время реакции |
| SLA | утверждённое соглашение об уровне обслуживания с измеримыми обязательствами; в текущем репозитории не определено |
| Привилегированный доступ | полномочие выполнять административные или инфраструктурные действия, недоступные обычной учётной записи |
| Переаттестация доступа | периодическое подтверждение того, что выданное полномочие всё ещё нужно, корректно ограничено и имеет владельца |
| Логическое удаление | сокрытие записи из обычного использования с сохранением отметки `deletedAt` или другого признака удаления |
| Отметка удаления (tombstone) | сохранённая запись с признаком удаления, которая передаёт это состояние между локальной базой и сервером до отдельной физической очистки |
| Физическое удаление | уничтожение конкретной строки, файла или объекта в названном хранилище |
| Остаточные данные | сведения, которые могут сохраниться после основной операции в другом хранилище, журнале, резервной копии, компоненте или пользовательском экспорте |
| Срок хранения | правило, связывающее категорию данных, начальное событие, продолжительность и способ удаления |
| Допуск ИИ | документированное решение о разрешении конкретного режима, поставщика и модели после проверки согласия, данных, безопасности, качества, эксплуатации и отката |
| Внедрение инструкций в данные | попытка заставить модель принять пользовательский текст или результат инструмента за управляющую инструкцию |
| Фиксированный пакет согласия | набор областей, который текущая реализация разрешает только целиком, без выбора отдельных категорий |
| Миграция данных | управляемое преобразование сохранённых объектов из старой формы в новую с учётом повторного запуска, остановки и проверки результата |
| Обратная совместимость | способность нового читателя безопасно принять данные поддерживаемой старой версии |
| Смешанный выпуск | период, когда предыдущие и новые клиенты одновременно работают с переходной серверной схемой |
| API | программный интерфейс взаимодействия компонентов |
| Серверный API-контракт | имя и способ вызова функции вместе с полномочием, входом, ответом, ошибками, побочными эффектами, лимитами и поведением при отказе |
| Публичная поверхность | функции и маршруты, доступные внешнему клиенту, включая защищённые входом и общим секретом |
| SLI | измеряемый показатель поведения сервиса: успешность, задержка, свежесть или полнота |
| SLO | утверждённая числовая цель для SLI на определённом окне и с точным методом расчёта |
| Бюджет ошибок | допустимая доля событий вне SLO на окне; не распространяется на запретные нарушения безопасности |
| Синтетическая проверка | периодическое выполнение контролируемой пользовательской операции для проверки доступности и корректности всей цепочки |

| Происхождение данных | сведения о первичном источнике, действующем лице, времени, преобразованиях, версиях и подтверждении сохранённого значения |
| Цепочка преобразований | последовательность операций от наблюдения или ручного ввода до производной записи и её передачи |
| Производная запись | значение, созданное из другой записи, алгоритма, правила, каталога или ответа модели |
| Доказательная ссылка | машиночитаемая связь производного объекта с записью-основанием; сама по себе не доказывает медицинскую истинность |
| Качество данных | пригодность значения для конкретной цели по полноте, допустимости, актуальности, согласованности и прослеживаемости |
| Цель обработки | конкретная причина сбора, использования, передачи или хранения определённых данных для определённого получателя |
| Явное включение функции | явное включение необязательного потока в приложении; не заменяет иные юридические основания |
| Разрешение ОС | системное право использовать камеру, медиатеку или уведомления; не разрешает сетевую передачу данных |
| Отзыв согласия | прекращение новых операций в установленной области; не равен удалению уже созданных данных |
| Версия текста согласия | устойчивый идентификатор показанного пользователю состава целей, данных и получателей |

## Правило употребления

При первом упоминании специализированного термина следует использовать русское определение. Имя технологии или сокращение допускается сохранить, если перевод ухудшает точность.
