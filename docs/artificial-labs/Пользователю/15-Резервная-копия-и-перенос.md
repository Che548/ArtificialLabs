# Резервная копия и перенос

Инструкция помогает сохранить поддерживаемые данные перед сменой устройства, переустановкой, крупным импортом или удалением. Пользовательский экспорт — переносимая копия, а не полное резервное восстановление приложения со всеми файлами и настройками среды.

> [!summary] Безопасная последовательность
> Создайте JSON-экспорт, отдельно сохраните исходные фотографии и документы, перенесите обе части, проверьте новое устройство и только после этого очищайте старое.

## Когда создавать копию

Подготовьте свежий экспорт перед:

- переустановкой приложения;
- сменой или передачей устройства;
- удалением локальных данных;
- крупным импортом;
- испытанием новой нативной сборки;
- выходом на общем устройстве;
- запросом удаления учётной записи.

Экспорт следует проверять сразу после создания. Наличие имени файла в системном меню не доказывает, что копия полностью записалась в выбранное место.

## Что переносит JSON

JSON содержит поддерживаемые структурированные сведения: профиль, программы, дневник, анализы, подтверждённые сканирования, напоминания, состояния здоровья, препараты, аллергии, метаданные документов, историю диалогов и настройки.

Он не содержит:

- фотографий тестов;
- содержимого лабораторных документов;
- локальных вложений диалогов;
- адресов файлов на старом устройстве;
- плана, автоматических правил и служебных событий помощника;
- серверной телеметрии;
- учётных реквизитов и токенов.

CSV переносит одну выбранную категорию и удобен для просмотра. Для основного переноса используйте JSON, а не набор разрозненных CSV.

## Подготовка копии

1. Откройте «Профиль» → «Экспорт данных».
2. Выберите JSON и сохраните файл в защищённое место.
3. Убедитесь, что файл имеет ожидаемый размер и открывается как текстовый архив.
4. Сохраните нужные фотографии и документы отдельно.
5. Запишите дату копии и устройство, с которого она создана, без добавления медицинских значений в имя файла.
6. Не удаляйте исходные данные до проверки нового устройства.

Если системное меню не подтвердило сохранение, повторите экспорт в другое защищённое место. Не отправляйте архив поддержке для проверки.

## Перенос на новое устройство

1. Установите поддерживаемую нативную сборку ArtificialLabs.
2. Войдите в нужную учётную запись.
3. При необходимости отдельно включите облачную синхронизацию.
4. Импортируйте JSON.
5. Сравните предварительное количество с ожидаемым.
6. Проверьте профиль, дневник, анализы, сканирования, документы и диалоги.
7. Отдельно перенесите нужные исходные файлы. Автоматического восстановления их связей из JSON нет.
8. Создайте новый экспорт уже на новом устройстве.
9. Только после этого очищайте старое устройство.

Не импортируйте архив в случайную учётную запись. Если на новом устройстве уже есть записи, импорт объединяет данные по идентификаторам и времени изменения; он не создаёт отдельный изолированный профиль для файла.

## Проверка полноты

Проверяйте не только общее число записей. Выберите по одному известному примеру из каждой важной категории и убедитесь, что:

- дата и тип записи совпадают;
- удалённая ранее запись не появилась снова;
- документ показывает корректные метаданные;
- отсутствие исходного файла обозначено явно;
- синхронизация не включилась без вашего решения;
- медицинское значение не изменилось после импорта.

Если результат отличается от ожидаемого, не повторяйте импорт вслепую. Сохраните исходный архив и зафиксируйте безопасные сведения: версию приложения, платформу, время, категорию и количество записей без медицинского содержимого.

## Защита архива

JSON и CSV содержат персональные данные. Для них действуют те же меры, что и для медицинского документа:

- ограничьте доступ к папке;
- не помещайте файл в публичный чат, задачу или репозиторий;
- не храните рядом пароль или токен;
- удалите временные копии после проверки;
- учитывайте корзину и историю версий облачного диска;
- не открывайте архив в недоверенном веб-сервисе.

После передачи файла другому приложению ArtificialLabs не может управлять его сроком хранения и удалением.

## Чего не заменяет экспорт

Пользовательский архив не заменяет:

- системную резервную копию устройства;
- отдельное сохранение исходных медицинских файлов;
- восстановление забытого пароля;
- проверенную инфраструктурную копию Convex;
- удаление данных со старого устройства;
- удаление учётной записи и серверных данных.

Облачная синхронизация также не является полной резервной копией: она передаёт только структурированные данные после отдельного согласия и не хранит содержимое исходных файлов.

## Перед очисткой старого устройства

- Новый JSON создан и открывается.
- Основные категории проверены вручную.
- Нужные исходные файлы сохранены отдельно.
- Состояние синхронизации понятно на обоих устройствах.
- Уведомления на старом устройстве отключены.
- Локальная очистка выполнена до выхода из общей учётной записи.
- Внешние временные копии учтены.
