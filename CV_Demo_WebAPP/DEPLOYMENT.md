# Изолированный выпуск CV-демо

Целевой адрес: `https://cv.sfera.brainwaves.engineering/`, без `/beta`.
Этот сервис не заменяет `admin/`, Convex, мобильное приложение или страницу установки.

## Сборка и доставка

Workflow `.github/workflows/cv-demo.yml` проверяет CV на синтетических данных и
собирает Linux amd64 image `ghcr.io/che548/artificiallabs:cv-latest`. Только проверенный
`main` публикует `cv-latest` и `cv-<полный SHA>`; PR не получает ключей развёртывания.
Используется уже публичный GHCR-пакет, без нового registry-токена на сервере.
Теги `latest` и `<SHA>` админки этот workflow не меняет.

На `junk` разместить `compose.yml` в отдельном каталоге
`/home/taras/deployments/artificiallabs_cv`, затем выполнить `docker compose pull`
и `docker compose up -d`. Отдельный Watchtower следит только за
`artificiallabs_cv`; существующий Watchtower админки не изменяется.
Сервис работает одним процессом, от непривилегированного пользователя, с лимитом
памяти и CPU. Порт доступен только на loopback `127.0.0.1:8095`.

## Ingress

В существующем Tailscale connector добавить только TCP 8095 → 127.0.0.1:8095,
не сбрасывая остальные правила Serve. В существующем Nginx Proxy Manager:

- host `cv.sfera.brainwaves.engineering`, upstream HTTP `100.64.0.37:8095`;
- отдельный действующий сертификат для этого имени и HTTPS;
- без переписывания пути, без кэширования;
- `client_max_body_size 13m;` и `proxy_request_buffering off;`, чтобы снимки
  не буферизовались Nginx во временные файлы; `proxy_buffering off;`;
- не включать логирование тел запросов и ответов.

DNS: A на адрес существующего ingress, DNS-only. Не добавлять новый TLS-прокси,
не отключать проверку сертификатов и не менять остальные хосты.

## Данные и проверки

Volume `cv-access` содержит только серверное состояние доступа и не публикуется.
Снимки обрабатываются в памяти, история остаётся в IndexedDB браузера. Не удалять
volume при обновлении и не копировать его в Git или отчёты.

`GET /api/health` возвращает только готовность CLI, без путей или секретов.
После доставки проверить HTTPS, страницу входа, 401 для анализа без сессии,
403 для неверного Origin и синтетический CV-сценарий. Реальную камеру проверять
отдельно на устройстве; браузерный fake-camera тест этого не заменяет.

Для локального E2E использовать уникальный временный `CV_DEMO_DATA_DIR`, никогда
не production volume. Тест реального пароля запускается только с отдельно
переданным `CV_DEMO_TEST_PASSWORD`; без него результат явно skipped.

## Откат

Остановить только `artificiallabs_cv_watchtower`, выбрать предыдущий проверенный
тег `cv-<SHA>` в image CV-сервиса и выполнить `docker compose up -d cv-demo`.
Сохранить volume. После устранения проблемы вернуть `cv-latest` и Watchtower.
Не использовать `docker compose down -v` и не откатывать остальные сервисы.
