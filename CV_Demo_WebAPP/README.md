# Сфера Scan — CV Demo WebAPP

Изолированная Next.js веб-версия flow сканирования из мобильного приложения. Создана в `main`; не подключена к существующему развёртыванию `admin/` и не меняет Expo web.

## Локальный запуск

Node.js 22+, CMake, OpenCV (core, imgproc, imgcodecs, dnn, calib3d/geometry), C++17.

```sh
# Из корня PrivateExpo
npm ci --prefix CV_Demo_WebAPP
npm run build:cv --prefix CV_Demo_WebAPP
npm run dev --prefix CV_Demo_WebAPP
```

Открыть `http://127.0.0.1:3040`. Данные администратора согласованы отдельно; проверка хранится только на сервере (`lib/auth.ts`, scrypt hash). Пароль в клиентский bundle не входит. Для сборки на macOS: `brew install cmake opencv`. На Debian: `apt-get install cmake g++ libopencv-dev`.

Для production-режима: `npm run build --prefix CV_Demo_WebAPP`, затем `npm run start --prefix CV_Demo_WebAPP`. Для публичного адреса задайте `CV_DEMO_PUBLIC_ORIGIN=https://...`, проксируйте на порт 3040 и используйте HTTPS. Камера работает на HTTPS или localhost. Приложение должно работать одним Node-процессом, без нескольких реплик; для нескольких реплик требуется заменить файловое хранилище доступа на транзакционную БД.

## Что работает

- Модалка входа, серверная HTTP-only сессия, выход и ограничение числа попыток.
- Пять шагов подготовки с иллюстрациями из приложения и настройкой пропуска.
- QR с камеры либо номер партии / встроенный профиль.
- Камера, переключение камеры, загрузка JPEG/PNG/WebP, предпросмотр и пересъёмка.
- Автоматический анализ: тот же C++ `LearnedReader`, пять ONNX-моделей и политика `strip-reader-experimental-20260914-r2`, что в мобильном приложении. Общий `adaptLearnedStripResult` проверяет и преобразует результат для интерфейса.
- Явная ручная корректировка углов/направления использует классический StripCV, как и соответствующий режим мобильного приложения.
- Отмена обработки, проверка результата, ручная корректировка четырёх углов и направления с повторным CV-анализом.
- Подтверждение результата пользователем. Невалидные и сомнительные результаты сохраняются только как требующие проверки, без автоматической классификации.
- История в IndexedDB, поиск, фильтры, редактирование, удаление и экспорт JSON.
- Гостевые ссылки на 1 час / сутки / неделю с отзывом; гости не управляют ссылками. Ссылки повторно используемые до истечения срока. Секрет передаётся во fragment и немедленно удаляется из адреса. Сервер хранит только его хеш. Отзыв инвалидирует созданные по ссылке сессии.

## Подключение CV

Самый короткий путь использует существующий защищённый `/api/analyze`: и файл, и снимок камеры проходят один обработчик. Обработка выполняется на сервере демо, не в WASM. Препроцессинг, OpenCV DNN inference и пороги не переписаны на JavaScript. Расположение, стили и действия интерфейса сохранены; непрерывное отслеживание полоски не добавлялось.

`npm run build:cv` сначала сверяет SHA-256 пяти весов, затем инкрементально собирает только `stripcv_cli`, в один процесс. Автоматический запрос запускает `stripcv_cli --learned MODEL_DIRECTORY`; RGB передаётся через stdin, JSON возвращается через stdout. Фотография не создаётся на диске. CLI ограничивает OpenCV одним вычислительным потоком. При отсутствии модели или несовместимом бинарнике запрос завершается ошибкой, без скрытой подмены старым алгоритмом.

Путь по умолчанию — `../modules/strip-cv/models/reader-20260914` относительно каталога демо; переопределение — `STRIPCV_MODELS`. При переносе сервера необходимы бинарник, OpenCV и все пять весов. Новые зависимости или скачивание весов браузером не требуются.

Препроцессинг входа сохраняет существующее поведение демо: браузер нормализует снимок и ограничивает длинную сторону 2400 пикселями. Совпадение результатов с мобильной версией проверяется для одинаковых RGB-пикселей; различия исходных снимков и JPEG-кодирования могут менять результат. Пайплайн выдаёт число линий и требует подтверждения; калиброванное T/C не вычисляется.

## Данные и ограничения

Снимок временно передаётся серверу демо для CV; фотографии и медицинские результаты не пишутся на серверный диск, в логи или Convex. Сохранение истории происходит только в браузере. История не синхронизируется между устройствами; очистка данных сайта удаляет её. Доступ по одному приглашению в одном браузере использует одну локальную историю; это демонстрационный доступ, а не личные медицинские аккаунты.

Состояние доступа (сессии, хеши приглашений, секрет подписи) хранится в `.data/access.json` с правами 0600. Каталог должен быть постоянным и не публиковаться. Для контейнера смонтируйте постоянный каталог и задайте `CV_DEMO_DATA_DIR`. Удаление каталога сбрасывает все сессии и ссылки. Не размещайте эту папку в public и не коммитьте её.

Обработка ограничена двумя одновременными CV-процессами, 30 секундами, 12 МБ на фото и 20 Мп. Браузер нормализует EXIF и уменьшает большую сторону до 2400 пикселей. Никаких внешних AI API и фиктивных CV-результатов. Встроенный профиль не содержит валидированного диагностического порога; распознавание линий не является диагнозом.

## Проверка

```sh
npm run build:cv --prefix CV_Demo_WebAPP
npm run verify --prefix CV_Demo_WebAPP
npm run test:e2e --prefix CV_Demo_WebAPP
npm run verify
```

Unit tests запускают настоящий CLI и пять ONNX-моделей на синтетических изображениях, сравнивают ответ серверного обработчика с прямым вызовом общего мобильного reader/adapter, проверяют ручную корректировку, отсутствие моделей и отмену. Playwright проверяет защищённый вход, инструкции, загрузку, реальный CV-путь для невалидного кадра, корректировку, историю и отзыв гостевого доступа. Скриншоты содержат только синтетические данные и находятся в игнорируемом `test-results/`. Доступ к физической камере и качество реальных тестов требуют отдельной проверки на целевом устройстве.

GitHub Actions `CI` устанавливает зависимости демо через `npm ci`, использует собранный общий StripCV, выполняет `verify` и два сценария загрузки/камеры из `learned-flow.spec.ts`. Для них используются только синтетические изображения и временная тестовая сессия, без пароля администратора и секретов GitHub. Публикация существующего образа `admin/` остаётся отдельным workflow; сам CV-сервер этим образом не развёртывается. Lock-файл `admin/` проверяется также npm 10 из Node.js, указанного в `.nvmrc`, чтобы чистая установка в Actions совпадала с локальной.

## Проверено локально

14 сентября 2026: сборка C++ StripCV с OpenCV 5, три CTest-проверки ядра, восемь unit-тестов веб-версии, production-сборка Next.js и общий `npm run verify` репозитория прошли. Для браузерных тестов установите `npx playwright install chromium`; проверка реального входа дополнительно использует серверную переменную `CV_DEMO_TEST_PASSWORD`. Пароль не записывается в тестовые файлы.

Все четыре Playwright-сценария прошли: реальный вход и выход, защита API, инструкции с возвратом к фото, нативный анализ и ручная рамка, история, мобильная вёрстка, гостевой вход и отзыв ссылки.

## Проверка подключения мобильного reader R2

Инкрементальная сборка `stripcv_cli`, контроль пяти SHA-256 и `npm run verify` из `CV_Demo_WebAPP` прошли: TypeScript, 11 unit-тестов и production-сборка Next.js. Два отдельных браузерных теста `tests/learned-flow.spec.ts` прошли через настоящий `/api/analyze`: загрузка синтетического PNG и снимок тестового видеопотока камеры. Оба сценария получили `strip-reader-experimental-20260914-r2` и отобразили результат в прежнем интерфейсе. Это проверка интеграции, не оценка точности на медицинских фотографиях; физическая камера не использовалась. Полная проверка Expo-приложения повторно не запускалась, его интерфейс и нативные сборки не менялись.
