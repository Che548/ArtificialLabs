# Сфера Scan — CV Demo WebAPP

Изолированное Next.js демо сканирования. Интерфейс сохранён; загрузка файла и
снимок камеры используют тот же C++ `LearnedReader`, шесть ONNX-моделей и общий
TypeScript-адаптер, что установленная iOS-сборка `r6-single`.
Текущая версия: `strip-reader-experimental-20260914-r6`.
Экспериментальные замены моделей в демо не включены.

## Запуск и сборка

Node.js 22+, CMake, C++17. Контейнер использует Debian 13 / OpenCV 4.10;
локальная сборка CLI поддерживает OpenCV 5. OpenCV 4.6 из Ubuntu 24.04 не
импортирует замороженный ONNX-детектор и для learned-демо не подходит.

```sh
npm ci --prefix CV_Demo_WebAPP
npm run build:cv --prefix CV_Demo_WebAPP
npm run dev --prefix CV_Demo_WebAPP
```

Адрес: `http://localhost:3040`. Production-режим: `npm run build --prefix
CV_Demo_WebAPP`, затем `npm run start --prefix CV_Demo_WebAPP`. Камера требует
HTTPS или localhost. Для внешнего адреса задайте `CV_DEMO_PUBLIC_ORIGIN=https://...`
и проксируйте порт 3040 через HTTPS. Логин администратора — `admin`; проверка
согласованного пароля хранится серверным scrypt-хешем и не входит в клиентский JS.
Инструкции развёртывания: [DEPLOYMENT.md](./DEPLOYMENT.md).

`build:cv` сверяет SHA-256 всех шести моделей по общему manifest и инкрементально
собирает CLI одним процессом. После обновления выполните `build:cv` и `build`,
затем перезапустите демо. Параметры `STRIPCV_CLI` и `STRIPCV_MODELS` задают пути;
по умолчанию используются `../web-build/stripcv-native/stripcv_cli` и
`../modules/strip-cv/models/reader-20260914` относительно каталога демо.

## Совпадение с приложением

Автоматический анализ использует C++ через защищённый `/api/analyze`, без WASM
и без отдельной JS-реализации inference. RGB передаётся CLI через stdin, ответ
возвращается через stdout. Результат проходит общий `adaptLearnedStripResult`.
Сервер отклоняет ответ, если его `algorithm_version` отличается от общего
manifest. `/api/health` показывает ожидаемую версию и проверяет доступность CLI
и шести моделей; сам health endpoint не запускает распознавание.

R6 допускает подтверждение одной линии при неопределённой оценке вспомогательной
модели только при сильном согласии основной и локальной моделей и прежних
проверках покрытия окна. Уверенное противоречие по-прежнему требует проверки.
Явная ручная корректировка углов/направления использует общий классический
StripCV, как соответствующий режим приложения.

Веб-демо и установленное приложение анализируют один снимок после кнопки.
Буферизация в приложении временно выключена; настройки камеры, физический
объектив 1× и полное качество снимка сохранены. Рамки, автофокус по детекции и
периодические проверки до нажатия кнопки относятся к нативной камере;
в веб-демо непрерывное отслеживание не добавлено.

Загрузки JPEG/PNG/WebP до 12 МБ, 20 Мп и 6000 пикселей по стороне передаются
без повторного JPEG-сжатия и уменьшения. Сервер один раз применяет EXIF-поворот,
приводит цвета к sRGB и накладывает прозрачность на белый фон. Проверка равенства
CV выполняется на одинаковых RGB-пикселях: оптика, обработка камеры, JPEG и
различия декодеров могут менять вход и результат на реальных фотографиях.
Пайплайн выдаёт число линий с обязательным подтверждением пользователем;
калиброванное T/C и диагностический результат не вычисляются.

## Доступ и данные

Модалка входа, HTTP-only сессии, ограничение попыток, выход, гостевые ссылки с
отзывом, ручная проверка результата и история в IndexedDB сохранены. Гости не
управляют приглашениями. Секрет приглашения передаётся во fragment и удаляется
из адреса, сервер хранит только его хеш.

Фото временно передаётся серверу демо для CV и не сохраняется на серверный диск,
в логи или Convex. История остаётся в браузере, не синхронизируется между
устройствами и удаляется при очистке данных сайта. Обработка ограничена двумя
одновременными CV-процессами и 30 секундами на запрос.

Сессии, хеши приглашений и секрет подписи хранятся в `.data/access.json` с правами
0600. Для контейнера задайте постоянный `CV_DEMO_DATA_DIR`; не публикуйте его и
не добавляйте в Git. Требуется один Node-процесс; несколько реплик потребуют
транзакционного хранилища доступа. Демо не подключено к `admin/`, медицинским
аккаунтам или Expo web. Его отдельный контейнер публикуется с тегами `cv-*`.

## Проверки и ограничения

```sh
npm run build:cv --prefix CV_Demo_WebAPP
npm run verify --prefix CV_Demo_WebAPP
npm run test:e2e --prefix CV_Demo_WebAPP
npm run verify
```

Unit/E2E проверяют настоящий C++-анализ, общий адаптер, загрузку, камеру с
синтетическим потоком, ориентацию, доступ и отклонение несовпадающей версии.
Синтетические изображения и inference проверяются на отдельной Linux VM;
локальные сборки и проверки кода не заменяют проверку камеры iPhone.

Все шесть SHA-256 и manifest сверены с установленным пакетом `r6-single`.
На прежних наборах разработки R6 сохранял 30/35 однолинейных и 110/117
двухлинейных ответов; новый набор однолинейных кадров — 7/9. Это повторно
использованные данные разработки, не независимая оценка точности.

Известное отдельное ограничение общего Linux CI: классический `faint_line_safety`
не проходил с системным OpenCV 4.x. Пороги и требования этого теста не ослаблены.
Успех сборки CV-демо не означает успех всех проверок классического анализатора.
